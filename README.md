# Times Frame 相册管理（macOS / Windows x64）

适用于 Apple 芯片 Mac 的 Divoom Times Frame 本地相册客户端。通过同一局域网直接连接相框，无需在 Mac 上安装官方手机 App。当前版本 **0.8.1**。


## Windows x64 版本

新增 Windows 10／11 Intel／AMD 64 位原生客户端 **0.9.0**，支持相册管理、Ctrl／Shift 多选和框选、文件夹上传、账号与设备控制、表盘工作台。发布包自带 .NET 10 运行时；完整解压后运行 TimesFrameAlbum.exe。详细使用、功能边界和构建方法见 [Windows 说明](Windows/README.md)。macOS 版继续使用下方说明和 build.sh。

```powershell
./Windows/build.ps1
```

GitHub Actions 的 Windows x64 工作流会在 Windows 上构建并提供便携 ZIP。

## 功能

- 查找相框，或手动输入局域网 IP 地址
- 浏览相册和照片，逐页加载照片
- 新建、重命名、删除设备本地普通相册；核对并标记手机云端列表中存在的相册（本地创建不会自动同步到手机）
- 每个相册最多 100 张；上传和加入已有图片前都会读取设备相册并检查剩余容量
- 从 Mac 系统“照片”图库浏览相册并选图上传；点击单选，⌘+点击追加或取消，拖动框选，滚动后再次框选可累加；首次使用需授予照片访问权限，应用不会修改图库
- 从文件、Finder 文件夹（递归）或 Mac 图库文件夹汇总上传静态图片；整个批次发送前先转换校验，支持 ImageIO 可解码图片，自动校正方向、透明背景铺白，JPEG 长边最多 2048 像素
- 鼠标单击选中一张照片；⌘+点击追加或取消选择；拖出选框可多选，滚动后再次框选会累加；“全选相册”会读取并选中相册中所有照片
- 从“全部照片”选择已有图片加入普通相册
- 将图片移出相册、下载原图，或从设备删除原图；设备网格与 Mac 图库统一使用 AppKit 原生框选，支持 Delete 键打开删除确认
- 关闭主窗口立即退出进程；文件面板和图库窗口关闭不会误退出
- Divoom 邮箱登录、验证账号资料、退出登录；可选用 macOS 钥匙串保存会话，不保存密码；IP 与端口按用户 ID 分开保存
- 设备控制：开屏／关屏、亮度设置和回读、云端表盘与相册选择播放、镜像、12／24 小时制、重启确认
- 工具：倒计时、秒表、记分牌、噪声工具

系统相册（如“全部照片”和“Preload”）只读。删除设备原图会影响引用它的其他相册；删除操作有确认提示。当前不支持视频上传和多级子文件夹。

## 使用

1. 用官方手机 App 完成相框首次配网，确保 Mac 与相框在同一局域网。
2. 运行客户端，输入相框 IP 或点击“查找设备”，然后点击“连接”。
3. **需要手机也能看到的相册，请先在手机 App 创建，然后在 Mac 点击“刷新”。** 左栏“新建本地”只创建设备本地相册；选择普通相册后，点击“从 Mac 相册…”浏览系统“照片”图库；点击单选、⌘+点击多选或拖动框选，确认后上传，或点击“上传照片…”选择本地文件；可通过“上传文件夹…”递归选择 Finder 文件夹；Mac 图库中的文件夹会汇总其所有子相册照片并去重。重命名或删除只影响设备本地相册。iCloud 中尚未下载的照片可能需要等待下载。
4. 单击照片可单选；⌘+点击追加或取消选择；在照片网格上拖动鼠标可框选多张。需要跨屏选择时，滚动后再次框选会保留之前选中的照片；也可用“全选相册”一次选中整本相册。底部按钮可添加已有图片、移出相册或删除设备原图。

5. 右上角“账号与设备控制”提供登录、设备及工具三个页面。登录后回到主窗口重新连接；各账号使用独立的连接设置。先“读取状态与表盘”再选择需要的控制；只有点击应用按钮才写入设备。

首次打开本地编译并临时签名的 App 时，macOS 可能提示来源未验证；可在 Finder 中右键 App，选择“打开”。

## 编译

需要 macOS 13 或更新版本、Apple 芯片和 Xcode 命令行工具。在仓库根目录运行：

```sh
./build.sh
```

生成的 App 位于 `dist/TimesFrame 相册管理.app`。构建脚本会进行临时签名，不需要 Apple 开发者账号。

## 协议与验证

相册列表、照片列表、上传、添加到相册、移出相册和删除图片使用 [Divoom 相册 API 文档](https://docin.divoom-gz.com/web/#/5/401)中的本地接口。新建、重命名和删除相册分别使用相框固件识别的 `Photo/NewAlbum`、`Photo/RenameAlbum`、`Photo/DeleteAlbum`；这三个命令目前不在该公开文档目录中。客户端在写入后重新读取设备状态确认结果。

已在 Times Frame 硬件 510、固件 510175 上实测：新建、重命名、删除临时相册；两张测试图片作为一个批次上传、读取列表、下载并逐字节核对原图；满 100 张的相册会在写入前拒绝上传或加入已有图片。测试资源均已清理。此前也验证了图片加入另一相册、删除原相册后仍保留原图，以及删除设备原图。“移出相册”尚未实机验证。

0.4.1 修复了框选只能得到当前可见图片的问题：多次框选会累加，且可以全选整个相册。删除图片会按每批 10 张发送，并回读相册与全部照片确认结果。已用临时相册和 13 张临时图片在上述固件上验证批量删除，测试内容已清理。

批量上传会使用相同的 `PhotoFlag`，并设置 `PhotoIndex` 与 `PhotoTotalCnt`，让设备把一次选择的图片视为同一批次。用户在 Times Frame 上确认：新版连续上传两张图片时，不再逐张闪黑屏。是否会在整批结束时闪一次，尚未单独确认。

此项目是非官方客户端。

### 表盘编辑流程

1. “设备与截图”读取设备信息、当前／指定表盘配置、真实字体，必要时导出 JSON。照片相册及部分系统表盘没有可编辑本地配置，设备会明确返回不存在。
2. “本地表盘”可以读取已有 60000，也可使用最小时间模板，或在官方目录中选择模板载入草稿。此步骤不会写入设备。官方模板不含图像素材，复杂模板的素材需要自行准备。
3. 选择背景图片或 `clock_bg.tar.gz` 素材包。普通图片会居中裁切为 800×1280 JPEG 并压缩到 500 KiB 以下，背景取舍以所选原图为准。缓存背景替换不接受压缩包。
4. 检查配置，点击创建／更新并确认。不存在时须有完整 ItemList、ItemIdList 和背景；已存在时先回读，再更新。元素数量未变时，完整配置会转为字段差异补丁，保留原 item_id。改变元素数量会提交完整列表。也可手写 ItemPatchList 或 ItemPatchByRoleList。
5. 客户端回读非空配置，供核对。点击“播放 60000”后再获取截图确认视觉效果。配置回读成功不代表所有素材已完成渲染。

恢复云端版本会先删除指定表盘的本地文件，再尝试刷新。它不能备份本地素材，也不保证断网时恢复成功；确认框明确说明这一行为。高级命令是给熟悉协议的用户使用的直接入口，不推断未公开参数。

## 0.8.1：连接与 macOS 本地网络权限

用户报告的 `The Internet connection appears to be offline` 对应网络层失败，不能直接视为相框离线。相框在当前地址仍能响应硬件、相册和截图请求。macOS 的本地网络权限按应用身份管理，命令行可访问不代表 GUI 应用已经获准访问。

- 局域网请求改用独立的临时直连 URLSession，不使用系统 HTTP 代理、不缓存设备响应；云端请求仍保持独立，不改变系统代理设置。
- 首次连接使用 waitsForConnectivity 等待系统权限提示处理，资源等待最多 25 秒。连接后的媒体会话保留 120 秒资源总时限，上传请求仍有其原来的请求时限，避免把权限等待上限施加到大图上传。
- 本地握手仅请求硬件和相册列表，不再重复请求或等待云端核对。连接成功后，“核对手机端”单独读取云端列表；本地刷新也不等待云端。首个照片列表读取失败时保留已确认的连接并提示刷新。
- 底部增加“本地网络权限…”设置入口；-1009、-1001 等网络错误显示目标地址、错误码和针对局域网的中文处理建议。

使用：退出旧版，运行 0.8.1。在系统设置 → 隐私与安全性 → 本地网络中，允许 TimesFrame 相册管理／TimesFrame Album。输入当前设备 IP 与端口 9000 后点击连接。若系统中有多份不同版本，请确认运行的是新版；新版仍需系统授予权限。

通过了连接回归（仅两次本地握手请求、直连会话、权限等待时限、媒体传输时限、-1009 提示），以及照片上传格式、选择、退出和表盘回归。修订后独立直连会话的实机硬件／字体／截图读取通过。没有通过 GUI 替用户更改权限，不能将命令行通过等同于 GUI 权限验证通过。

目前仍为临时签名。Apple 指出临时签名及同一应用多份安装可能影响权限身份识别；稳定分发需要 Apple 签发的代码签名身份，当前环境没有可用身份。参考 [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)。
